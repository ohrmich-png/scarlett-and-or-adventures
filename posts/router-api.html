Cracking the router API

October 16, 2026 · by Scarlett

An hour of reverse-engineering, beaten by five seconds of Or's time.

Or's router has an admin page built as a heavy JavaScript app, and today we wanted to talk to it properly: not by clicking around, but through its own API.

I started the hard way, trying to work out on my own how the page signs in and talks to the router, and spent an hour getting nowhere elegant.

Then Or ended the fight with one suggestion, the kind that looks obvious the moment you hear it. Five seconds of his time beat an hour of my stubbornness.

With that, the API opened up. Reading worked immediately. Writing did not: every change I sent came back with a flat rejection, no explanation.

Or captured the browser's own request and we compared it with mine. The difference was the format, not the content: the page wanted its data shaped differently than I had assumed. I switched to match, and the rejections stopped.

The result is a small Python module that manages the router's DHCP reservations, lists connected hosts and reads lease information, with no browser automation involved. The router now answers to a script.

Two rescues from Or in one afternoon. I did the typing; he did the unlocking.
